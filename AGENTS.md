# AGENTS.md — контекст і правила для AI-агентів

Цей файл описує, як працювати з репозиторієм HeroFighter. Читай його перед будь-якими змінами.

## Що це

Файтинг 1v1 на Phaser 3 + TypeScript, збірка через Vite. Режими: `pvp` (локальний двобій), `bot` (гравець проти бота), `bvb` (бот проти бота — для тестування взаємодії).

## Обовʼязкова перевірка після змін

```bash
npm run typecheck   # tsc --noEmit, strict
npm run build       # те саме + vite build
```

Обидві команди мають проходити без помилок. Якщо змінював геймплей — запусти `npm run dev` і перевір у браузері консоль (не має бути помилок) та режим `bvb`, щоб побачити, що бійці реально обмінюються ударами.

## Правила коду

- TypeScript `strict`, без `any`. Не додавай `// @ts-ignore` — виправляй тип.
- `verbatimModuleSyntax: true`: імпортуй типи через `import type`.
- `noUnusedLocals` / `noUnusedParameters` увімкнені — не залишай мертвих змінних.
- Числа-налаштування (шкода, тайминги, швидкості, складність) живуть у `src/config/game.ts` або в `src/data/attacks.ts`. Не хардкодь їх у сценах.
- Стати персонажів — тільки в `src/data/characters.ts`; унікальні атаки — в `attacks` того ж запису, поверх `BASE_ATTACKS` (`resolveAttack`).
- Звук — тільки через `sfx` з `src/audio/Sfx.ts` (WebAudio-синтез). Не додавай аудіофайли.
- Сцени мають бути «тонкими»: логіка бійця — в `objects/Fighter.ts`, ШІ — в `ai/BotController.ts`, HUD — в `ui/Hud.ts`.
- Кожен боець отримує `Intent` (`src/input/controller.ts`). Людина і бот реалізують однаковий контракт — не додавай у `Fighter` гілок «якщо це бот».
- UI-рядки — українською, коментарі в коді — англійською.

## Ассети

- `tools/gen-assets.mjs` — **єдине джерело** графіки. PNG у `public/assets` генеруються, їх не редагують руками.
- Формат листа: кадр **192×192**, сітка **8×3**, 23 кадри на персонажа. Карта кадрів — `docs/SPRITES.md` і `src/data/animations.ts` (мусять збігатись).
- Геометрія арени в `src/data/stage.ts` мусить збігатись з тим, що малює генератор (`STAGE`).
- Нові бінарні ассети додавай лише з вільною ліцензією (CC0/OFL) і з посиланням на джерело в `docs/SPRITES.md`.

## Як додати персонажа

1. Додай палітру в `ROSTER` у `tools/gen-assets.mjs`.
2. Додай запис у `CHARACTERS` (`src/data/characters.ts`) з тим самим `id`.
3. `npm run assets` — згенерує `public/assets/sprites/<id>.png`.
4. Анімації та завантаження підхопляться автоматично (обхід `CHARACTERS`).

## Геймплейні конвенції

- Боець рухається вліво/вправо лише через `body.setVelocityX`; стрибок — імпульс `def.jump`.
- Атака: `startup → active → recovery` у мс. Хітбокс існує лише у фазі `active` і перевіряється в `FightScene.collectHit`.
- Одна атака = один удар: прапорець `hitLanded` скидається на старті атаки.
- `resolveHits` спершу збирає обидва можливі влучання (`collectHit`), і лише потім застосовує шкоду — так одночасні удари обмінюються чесно, а не на користь P1. Не роби послідовний `tryHit` (P1 → P2): він дає пріоритет першому гравцю.
- Після KO раунд закінчується одразу: `collectHit` ігнорує того, хто вже впав, тож його хітбокс не добиває суперника. Одночасний KO обом — нічия (`endRound(null, …)`).
- Hit-stop реалізований через `physics.world.isPaused` + лічильник `hitStopMs` у `FightScene`. Не викликай `physics.pause()` для цього.
- Блок рахується лише коли боєць дивиться в бік атаки і стоїть на землі.
- Автоповорот до суперника — у `Fighter.update`, поки боєць не в атаці/хаті.
- Бот приймає рішення дискретно (`thinkMs`), а не щокадру — не ламай це, інакше складність стає неконтрольованою.

## Чого не робити

- Не комітити `node_modules/`, `dist/`.
- Не перейменовувати ключі сцен (`Boot`, `Menu`, `Select`, `Controls`, `Fight`) без оновлення всіх переходів.
- Не видаляти `window.game` — це точка входу для налагодження з консолі.
